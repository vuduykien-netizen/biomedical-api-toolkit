# Biomedical API Toolkit: a beginner's guide

[Tiếng Việt](getting-started.vi.md) · [Repository overview](../README.md) · [API catalog](../references/api-catalog.md)

## 1. What is this toolkit?

Biomedical API Toolkit helps you obtain and check information from public research sources. You can use it to prepare a literature search, check a bibliography, inspect registered studies, or collect a small real dataset for a lesson or research exercise.

An **API** is a way for a program to request information from a service. Instead of copying each record by hand from a website, you send a query and receive structured results. A **skill** is a set of instructions an AI agent follows to perform a task. This toolkit combines that skill with an API catalog and a Python helper.

You do not need to learn all 14 APIs before using it. Start with one task and one or two suitable sources.

| You want to… | Start with… | What you can request from the agent |
|---|---|---|
| Find biomedical papers | MeSH, PubMed, Europe PMC | A search strategy and candidate article table |
| Check references generated by AI | Crossref, PubMed | A table of matches, discrepancies and unresolved references |
| Inspect study registrations | ClinicalTrials.gov | A table of designs, enrollment fields, status and registry links |
| Teach data cleaning or time-series plotting | World Bank | An extract, data dictionary, reproducible transformation and chart |
| Explore specialized drug or biological data | RxNorm, openFDA, ChEMBL | A scoped extract with the appropriate interpretation limits |

The toolkit is useful to students, researchers, educators and developers. It does not replace full-text reading, methodological appraisal or domain expertise. The three complete application directions are recorded in the [roadmap](../references/roadmap.md); they are not prebuilt applications included in the repository.

## 2. Choose your way of using it

**Route A — ask an AI agent.** Best if you want to describe a task in ordinary language. Install the skill in a compatible client such as Codex. The agent chooses sources, makes permitted requests and prepares the artifact you ask for. You do not need to write code yourself. The client needs network access and suitable tools for live retrieval; it needs Python if it runs the included helper.

**Route B — run Python yourself.** Best if you want direct control of queries or to integrate retrieval into your own scripts. The helper requires Python 3.10+ and uses only its standard library. No AI client is needed. It returns source data, not an automatically verified bibliography or completed analysis.

The repository is free to use under MIT. API providers may require a free key or impose allowances. An AI client's subscription or model charges are separate. Start with the no-key examples below; check the [dated catalog](../references/api-catalog.md) before scaling up.

## 3. Install for Route A

### Ask the installer

In Codex, enter:

```text
Use $skill-installer to install the skill from
https://github.com/vuduykien-netizen/biomedical-api-toolkit.
The skill is at the repository root.
```

If you prefer manual installation, use one of the following methods. Do not create a second copy if the skill is already installed.

### Manual installation with Git

The current [official local skill documentation](https://learn.chatgpt.com/docs/build-skills) lists `~/.agents/skills` for user skills. Some installations use `~/.codex/skills` or a custom skills directory. Choose your client's supported directory rather than duplicating the skill in both locations.

Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.agents\skills" | Out-Null
git clone https://github.com/vuduykien-netizen/biomedical-api-toolkit.git "$env:USERPROFILE\.agents\skills\biomedical-api-toolkit"
```

macOS / Linux terminal:

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/vuduykien-netizen/biomedical-api-toolkit.git ~/.agents/skills/biomedical-api-toolkit
```

### Manual installation without Git

1. Open the [GitHub repository](https://github.com/vuduykien-netizen/biomedical-api-toolkit).
2. Choose **Code → Download ZIP**, then extract it.
3. Rename the extracted folder to `biomedical-api-toolkit`.
4. Put that folder inside your client's skills directory.
5. Confirm the layout is `skills/biomedical-api-toolkit/SKILL.md`, with `scripts/`, `references/` and `docs/` alongside it. Avoid an extra nested repository folder.

Open a new session or restart your client if it has not discovered the skill. Type `$biomedical-api-toolkit` in a Codex prompt and check whether the skill can be selected. Other clients have their own installation and invocation rules. Pasting the name into an ordinary chat does not itself install the files or grant API access.

## 4. Try your first AI task

Start with a small request that makes the evidence easy to inspect:

```text
Use $biomedical-api-toolkit to find up to 5 candidate papers about
hypertension and medication adherence in PubMed. Show the exact search
query, retrieval date, title, year, PMID/DOI where available, and source links.
Explain what this small search does not cover. Do not present it as a
completed systematic review.
```

You should receive a recorded query, a candidate table, source links and limits. Some records may lack a DOI or abstract. If live access fails, the agent should say so and distinguish a proposed search from retrieved results.

For better requests, specify the topic, population, years, sources, maximum records and desired output. You can write in your preferred language; biomedical databases often need English search terms.

### Copyable prompts for the three tracks

**Literature discovery:**

```text
Use $biomedical-api-toolkit to prepare a literature search on [my question].
Population: [population]. Years: [range]. Propose MeSH and free-text terms,
then retrieve up to 10 candidates from PubMed and Europe PMC. Save the
queries and deduplicate by identifiers. Export a table with source links.
```

**Citation checking:**

```text
Use $biomedical-api-toolkit to check the bibliography pasted below.
Compare DOI/PMID, title, authors, year and journal. Return matched,
mismatched, ambiguous or unresolved, with a reason and source link.
Keep identity verification separate from whether a paper supports a claim.
[Paste references here.]
```

**Teaching data:**

```text
Use $biomedical-api-toolkit to obtain Vietnam life-expectancy data for
2010–2023 from World Bank. Preserve the raw response, query, retrieval
time, indicator definition and units. Prepare a CSV and a reproducible
transformation script, report missing values, and plot the annual series.
Explain the limits of interpreting country-level data.
```

Tables, CSV exports and charts require the agent to prepare them; the fetch helper alone does not produce them.

## 5. Try Route B: your first Python request

Download or clone the repository into a working folder, or use the already installed skill folder. Open a terminal **inside the toolkit folder**: it should contain `SKILL.md`, `scripts/` and `references/`.

Check Python:

```bash
python --version
```

Use Python 3.10 or newer. If your system uses `python3` or Windows `py`, use that command instead of `python` below. If Python is missing, obtain it from [python.org](https://www.python.org/downloads/).

First, inspect the request without contacting a provider:

```bash
python scripts/fetch_api.py pubmed --demo --dry-run
```

Then retrieve a tiny real result and save it:

```bash
python scripts/fetch_api.py pubmed --demo --output results/pubmed-first.json
```

The demo searches for `diabetes` and requests one PMID. It demonstrates access, not a complete search. Its ESearch response contains identifiers; it does not fetch all abstracts or full texts. Use the [catalog's EFetch example](../references/api-catalog.md) or ask the agent to retrieve details for selected PMIDs.

The helper creates `results/` if needed. It refuses to overwrite an existing output: choose a new name for another run. If you downloaded a ZIP, run commands from the extracted folder rather than inside the ZIP archive.

### Read the saved JSON

**JSON** is structured text with field names and values. Open the file in a text editor. The outer fields describe the request; `data` contains the provider response.

| Field | Meaning |
|---|---|
| `provider` | Which registry entry was queried |
| `request.url` | Query URL, with configured credentials redacted |
| `retrieved_at_utc` | Time the response was obtained, in UTC |
| `http_status` | Transport status; 200 means an HTTP response succeeded |
| `dry_run` | True for a plan without a network request |
| `data` | Provider records, messages or text |

For the PubMed demo, inspect `data.esearchresult.idlist` for returned PMIDs and `data.esearchresult.count` for the total number of matching records. A total count is not the number downloaded: this demo requests only one ID. A status of 200 does not exclude a provider error or empty result inside `data`.

## 6. Customize a request

Search for two bibliographic candidates:

```bash
python scripts/fetch_api.py crossref --path works --param "query.bibliographic=hypertension medication adherence" --param rows=2 --output results/crossref-first.json
```

Retrieve a small Vietnam time series:

```bash
python scripts/fetch_api.py worldbank --path country/VNM/indicator/SP.DYN.LE00.IN --param date=2010:2023 --param format=json --param per_page=50 --output results/vietnam-life-expectancy.json
```

`VNM` identifies Vietnam; `SP.DYN.LE00.IN` is the life-expectancy-at-birth indicator. Read its definition, units and source in [World Bank indicator metadata](https://api.worldbank.org/v2/indicator/SP.DYN.LE00.IN?format=json). Preserve missing values and data years before analyzing.

| Option | Purpose |
|---|---|
| Provider, e.g. `pubmed` | Select a source from the registry |
| `--demo` | Start with that provider's small example |
| `--path` | Select an endpoint relative to the provider's API base |
| `--param "key=value"` | Add a query parameter; repeat for additional fields |
| `--dry-run` | Inspect a plan without requesting data |
| `--output` | Save to a new JSON file |

Provider parameter names differ. Quote the entire `key=value` argument when it has spaces. Do not put a full URL or query string in `--path`. For custom requests, provide `--path` or use `--demo`. Consult [all provider examples](../references/api-catalog.md).

## 7. Keys, errors and updates

Small PubMed, MeSH, Crossref, ClinicalTrials.gov and World Bank examples can be tried without a key. Unpaywall requires a contact email. Other providers may recommend or require registration or have free allowances. Follow the [credential setup](../references/api-catalog.md) and use environment variables, not committed files or chat messages containing secrets. The helper does not check an account's billing settings.

| What you see | What to do |
|---|---|
| Skill does not appear | Check the folder layout and supported directory; open a new session or restart the client |
| `git` is not recognized | Use ZIP installation or install Git from [git-scm.com](https://git-scm.com/downloads) |
| `python` is not recognized | Try `python3` or `py`, or install Python and open a new terminal |
| Script file not found | Change into the toolkit folder containing `scripts/` |
| `Provide --path or --demo` | Add the endpoint or select the example |
| `Output already exists` | Use a new output filename; previous results are preserved |
| HTTP 429 | Stop repeated requests, wait according to the provider policy, or use its permitted free-key access |
| HTTP 403 | Check the official endpoint, access requirements and network restrictions |
| `Set UNPAYWALL_EMAIL locally` | Configure your contact email as described in the catalog, or use another source |
| No records or missing fields | Inspect query, date filters and provider messages; report the gap instead of inventing values |
| Network failure | Preserve previous outputs and retry later within a bounded scope |

For a Git installation, save your edits and run `git pull --ff-only` **inside the existing toolkit folder** to update. If it refuses because of local changes, preserve them before resolving the conflict. For ZIP installations, extract an updated copy into a separate folder and keep your own results. No automatic update or monitoring job is created.

## 8. Decide what the result actually establishes

A matching reference confirms bibliographic identity; it does not establish a paper's quality or prove a sentence is supported. A small search is not a completed systematic review. A registry record is not proof of treatment efficacy. Country-level data do not establish individual-level causation, and FAERS report counts cannot estimate adverse-event incidence. Preprints need clear labeling and a current publication-status check.

Keep identifiable patient data out of public API queries. Check source licenses before redistributing text, figures or datasets. These are practical limits of the sources used; the toolkit helps preserve them alongside your output.
